Rongoe — nieuwe MacBook (korte stappen)
========================================
GitHub: https://github.com/joeryvdberg/rongoe  (branch: main)

1) Software
   - Node.js LTS: https://nodejs.org
   - Git: Terminal → xcode-select --install

2) Project binnenhalen (geen handmatig kopiëren van code nodig)
   mkdir -p ~/Projects
   cd ~/Projects
   git clone https://github.com/joeryvdberg/rongoe.git
   cd rongoe

3) Dependencies
   npm install

4) .env
   Voor dit project hoef je normaal GEEN .env te zetten om lokaal te starten:
   Supabase staat nu in src/App.jsx.
   (Wil je later overstappen op VITE_* variabelen: maak dan .env en haal de waarden
   uit Supabase Project Settings → API — zelfde idee als Lyyve.)

5) Starten
   npm run dev
   Open de URL die Vite toont (meestal http://localhost:5173 )

6) Optioneel
   npm run build
   npm run lint

Deploy
   GitHub Actions deployt naar Pages na push naar main; check repo Settings → Pages.

────────────────────────────────────────────────────────────────────────
7) Supabase — “Ik ben erbij” (aanwezigheid voor de eerstvolgende wedstrijd)
────────────────────────────────────────────────────────────────────────

Waarom?
   De app slaat op wie op het rooster staat en zich heeft gemeld voor de eerstvolgende
   wedstrijd. Daarvoor is één extra tabel in Supabase nodig.

Stap A — Log in op Supabase
   1. Ga naar https://supabase.com en open jouw project (hetzelfde project als waar
      je players / schedule al in staan).

Stap B — Open de SQL Editor
   2. In het linkermenu: klik op “SQL Editor”.
   3. Klik op “New query” (of een leeg query-venster).

Stap C — Plak dit script en run het
   4. Plak onderstaande tekst in het venster.
   5. Klik op “Run” (of Cmd/Ctrl + Enter).

   ----- begin SQL -----
   create table if not exists public.match_presence (
     match_date text not null,
     player_id bigint not null references public.players(id) on delete cascade,
     confirmed_at timestamptz not null default now(),
     primary key (match_date, player_id)
   );

   alter table public.match_presence enable row level security;

   drop policy if exists "match_presence_anon_all" on public.match_presence;

   create policy "match_presence_anon_all"
     on public.match_presence for all
     using (true) with check (true);
   ----- einde SQL -----

   (De policy zorgt dat de app met dezelfde “anon” API-sleutel als de rest mag lezen
   en schrijven — net als bij je andere tabellen.)

Stap D — Controleren
   6. Ga naar “Table Editor” in het menu.
   7. Je zou nu de tabel “match_presence” moeten zien.
   8. Na het eerste vinkje in de app verschijnt hier een rij (match_date + player_id).

Klaar. Geen aparte API-keys nodig als de rest van de app al tegen dit project praat.
